## Database

Hand-written PostgreSQL DDL in `database/ddl/` (numeric folder order), run with `psql`; no
migration tool, no ORM. All tables live in schema `nss` (`search_path` = `nss, public`). Bootstrap:

1. `database/scripts/00_create_database.sql` (superuser) — DB + roles `nss_db_owner`,
   `nss_db_backend`, `nss_db_writer`; set passwords with `ALTER ROLE`.
2. `01_extensions.sql` (superuser) — pgcrypto/pg_trgm/btree_gin/postgis, `nss` schema.
3. `02_build.sh`/`.ps1` (as `nss_db_owner`) — all DDL + seed in phase order (phase/table
   inventory: `database/README.md`). `02_build.sh`/`.ps1` (and `render_build.sh`) are **existence-gated**
   (`run_ddl`/`run_seed`, `Invoke-Ddl`/`Invoke-Seed` in the `.ps1`; `to_regclass('nss.<t>')`): an existing
   table's DDL **and seed** are skipped, so only new tables get created/seeded — editing an existing
   table's DDL/seed needs a full rebuild. Also grants `nss_db_backend` read-only and
   `nss_db_writer` SELECT/INSERT/UPDATE on all `nss` tables (incl. future ones; no DELETE, no
   DDL), and seeds the admin superuser via `scripts/bootstrap_admin.py` (needs a runtime Argon2
   hash; default login `SS1`/`P1`, password `Admin@123`; INSERT-only with `WHERE NOT EXISTS`,
   never resets an existing password).
4. `03_validate.sh`/`.ps1` — row-count/FK checks (minimums only WARN, never fail);
   Family/Membership/`system_event_log`/`credential_sequence_counter` get existence checks only.

Governance DDL (10 tables, `ddl/08_governance/`) runs as build Phases 11b/11c and Correspondence DDL (5 tables incl. `correspondence_approval_step`, `ddl/09_correspondence/`; API in `correspondence.py`) as Phase 11d; Attendance DDL (4 tables, `ddl/10_attendance/`; API in `attendance.py`) as Phase 11e; Organization re-parent approval DDL (2 tables `organization_reparent_request`/`organization_reparent_step`, files `ddl/02_organization/06`-`07`, API in `org_reparent.py`) as Phase 11f; Assets & Property DDL (7 tables, `ddl/11_assets_property/` + guard triggers; API in `assets_property.py`) as Phase 11g; live-refresh marker DDL (1 table `live_change_marker` + sequence, `ddl/12_live_refresh/`; API in `live.py`) as Phase 11h (79 tables total); changing existing-table DDL (e.g. `election.election_type`, widened `admin_scope` CHECK) needs a full rebuild. Optional Phase 15 loads gitignored `seed/demo/nss_demo_seed.sql` when `RUN_DEMO_SEED` is truthy (not mirrored in `render_build.sh`).

**Audit-actor FKs (owner 2026-11-04, build Phase 13c):** every `*_by_sangha_sevi_pk` column in schema `nss` has a FOREIGN KEY to `nss.sangha_sevi`, added by ONE idempotent catalog-driven patch (`ddl/13_audit_actor_fk/01_audit_actor_fk_patch.sql`, `run_sql` on every build, wired in `02_build.sh`/`.ps1`/`render_build.sh`; `fk_<table>_<column>`, `NOT VALID` first so dangling legacy values cannot break a rebuild, then a VALIDATE attempt that only WARNs; existing FKs on such columns are left alone). New tables just declare a plain nullable UUID `*_by_sangha_sevi_pk` — never hand-write the FK or edit the patch; a non-Sangha-Sevi actor must write NULL (a bogus uuid is rejected). `03_validate` WARNs on missing / still-NOT-VALID actor FKs; diagnostic SELECT for dangling values: `database/scripts/README.md`. `system_event_log.actor_sangha_sevi_pk` is not covered. Tests: `tests/db/test_audit_actor_fk.py` (never run against a DB).

A fresh build seeds **no demo Person/Family/Membership data** — only reference data, 175 real
Sakha branches and the one admin. Real data arrives via `POST /api/v1/register` → admin
`POST /api/v1/admin/claims/{pk}/approve`.

- `.sh`/`.ps1` script pairs must stay operationally identical (shell wrappers only).
- **`render_build.sh` (repo root) duplicates the build sequence for Render/Neon** — keep it in
  sync with `02_build.sh`. `RUN_DB_BOOTSTRAP` (truthy = `true`/`1`/`yes`/`on`, case/whitespace-insensitive; default off) gates **only** Phase 13 (admin seed); all DDL/seed phases run every deploy, existence-gated. Known drift: no `postgis`, a Phase 13 failure only warns, `render.yaml` declares an unused `DATABASE_URL`, and
  `npm install` in a `runtime: python` service is untested. Render deploys on Python 3.14.0 (`render.yaml`). Env templates for the DEV and PROD portals (each with its own Neon project, own roles/secrets) are in `deploy/` (`*.env.example`; filled `deploy/*.env` is gitignored); the hard-rebuild and Neon setup steps are in the `render_build.sh` header. `DB_SSLMODE`/`DB_CHANNEL_BINDING` are read by nothing — the libpq variable is `PGSSLMODE`. A table's DDL file must carry all its columns/constraints in `CREATE TABLE` (no trailing `ALTER` safety nets: `run_ddl` skips the whole file for an existing table); changes to existing tables go in a separate `run_sql` patch.
- `nss_db_*` = PostgreSQL roles (lowercase); `NSS_ERP_*` = application RBAC roles in
  `role_master` (uppercase) — separate security boundaries.
- Naming: tables `snake_case`; internal PK `_pk`; FKs reference PKs, never business IDs; business
  IDs `_id` (`person_id`, `sangha_sevi_id`), codes `_code`. Business IDs are unpadded (`P1`,
  `SS1`, `SKH1`, `F1`). Audit columns `created_/updated_/deleted_at` + `*_by_sangha_sevi_pk` +
  `is_active` (soft delete; history is never hard-deleted).

## Architecture

FastAPI + raw psycopg2 (`api/`), static Tailwind/DaisyUI/Alpine frontend served by the same app
(`frontend/`). Routers → `api/schemas/` (Pydantic) with shared logic in `api/helpers.py` and
`api/services/` (`family_graph.py` BFS, `auth_service.py` Argon2/JWT, `rbac_service.py`
permission + admin-scope loading). 19 routers, 284 endpoints (registered routes in the working tree: 272 `@router.*` decorators + the 12 property/asset CRUD routes that `assets_property.py::_register_entity_routes` adds with `add_api_route`, so a decorator grep alone undercounts by 12; 252/17 on `develop`, 137/12 at v0.11.0); inventory: `docs/03_Solution/api/API_CONTRACT.md`.

**Two DB pools** (`api/database.py`; each fronted by a semaphore — a request WAITS up to `DB_POOL_WAIT_SECONDS` (20) for a free connection, then 503 + `Retry-After`; idle-dead connections are replaced; never call `pool.getconn()` directly in request code — use `get_connection`/`checkout_write`; the 2026-11-09 Render 500s were `PoolError: connection pool exhausted`, worsened by every page running `init()` twice via `x-init="init()"` — Alpine 3 auto-runs `init()`, so never add that attribute; `tests/api/test_db_pool_guard.py`, `tests/ui/test_ui_alpine_init.py`): `get_connection` = `nss_db_backend` (SELECT-only) for reads;
`get_write_connection` = `nss_db_writer` for every write endpoint. `tests/conftest.py` overrides
both to yield one session-scoped writer connection, wrapping each test module in a `SAVEPOINT`
rolled back at teardown — that is what lets the suite pass on a seed-less DB.
