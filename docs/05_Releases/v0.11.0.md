# Overview

Tier 5 turns the read-only Tier 0-4 slice into a working, authenticated, writable system. It adds
login (Argon2 + JWT, server-side sessions), RBAC with admin-scoped administration, self-registration
with an admin-approved claim flow, member-proposed geography with admin approval, and a complete
audit trail (row-level and field-level). The Tier 0-4 verification pages are replaced by
`login`, `register`, `dashboard` and `admin`.

---

# Features Included

## 1. Authentication (API + Database)

- `user_account`, `password_history`, `registration_claim`, `password_reset_token`, `user_session`
  tables; Argon2 password hashing and JWT access/refresh tokens (`api/services/auth_service.py`).
- Server-side sessions: `GET/DELETE /auth/sessions`; logout revokes the session.
- Forgot-password flow is inline on `/login`; OTP delivery is not implemented (visible only via `otp_debug`).

## 2. Administration and RBAC

- `user_role` and `admin_scope` tables; permission gates (`require_permission`) on Foundation,
  Organization, Person and Membership endpoints, plus admin scope (subtree) enforcement.
- Admin bootstrap superuser (`SS1` / `P1`) seeded by `scripts/bootstrap_admin.py`.
- `admin.py::update_status` refuses to activate an account without an active `sangha_sevi`.

## 3. Registration and Claim Flow

- `POST /register` always creates a `person`; a `user_account` (`PENDING_APPROVAL`) and
  `registration_claim` only when `has_membership` is true.
- New public `POST /register/lookup-existing` and `POST /register/claim` let a membership-less
  registrant return later (person ID + date of birth).
- `sangha_sevi` is created on admin approval (`claim_approval.py`).

## 4. Audit Trail

- DB trigger `fn_audit_trigger()` writes `system_event_log` and field-level `field_change_log`.
- Actor identity flows from the `nss.actor_*` session variables set on the write connection.
- Separate write pool (`nss_db_writer`: SELECT/INSERT/UPDATE, no DELETE, no DDL).

## 5. Member-Assisted Geography

- Members propose districts, postal codes, post offices and cities/villages via
  `POST /foundation/*/propose`; admins approve under `/admin/geo-entries`. `post_office` reinstated.

## 6. Build and Deploy

- `02_build.sh`, `02_build.ps1` and `render_build.sh` are existence-gated (`to_regclass`): existing
  tables keep their DDL and data; only new tables are created and seeded.
- `RUN_DB_BOOTSTRAP` gates only the Phase 13 admin seed on Render.

# Known Gaps

- `/register/lookup-existing`, `/register/claim` and `/person/{pk}/membership-summary` have no tests.
- Three independent `INSERT INTO nss.sangha_sevi` sites (`approve_claim`, `create_user`, `create_sangha_sevi`).
- Audit-actor FKs (`*_by_sangha_sevi_pk`) remain unconstrained.
- `02_build.ps1` existence gate has not been run under PowerShell.
- Deferred: mobile/email verification, i18n, Governance (Tier 6), Kumari/Kishor/Sevak (Tier 9), Mahila (Tier 10).
