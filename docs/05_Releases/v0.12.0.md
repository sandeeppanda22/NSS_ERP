# Overview

Tier 6 adds the organisation's governance and day-to-day operating modules on top of the Tier 5
authentication and administration base: governance bodies and elections, the correspondence register,
weekly Sangha Puja attendance, Sakha re-parent approvals, the Assets & Property module, optional
encrypted Aadhaar capture, an automatic data-refresh feed for the web UI, and audit diagnostics.
It also hardens the deployment: database connection pooling, response compression and a Render/Neon
setup (Python 3.14.0 on Render, per-environment env templates).

The release grew from 137 endpoints / 12 routers / 48 tables (v0.11.0) to 284 endpoints / 19 routers / 79 tables.

# Features Included

## 1. Governance (Module #8)

- 10 tables (`database/ddl/08_governance/`), 56 endpoints in `api/routers/governance.py`: bodies, body types,
  positions, assignments, acting assignments, elections, nominations, secret-ballot votes and results.
- Ballot-immutability triggers, DB-level seat-count limits and a live-nomination re-file index.
- §63 composite auto-grants (`NSS_ERP_ADVISORY_BOARD_ADMIN`, Kendra Governing Body scope) resolved from live seats.
- Advisory Board organisation type and the NULL-organisation scope levels (`KENDRA_MAHILA_SANGHA`, `ADVISORY_BOARD`)
  — GDR-005 / GDR-006 (Approved 2026-11-01).

## 2. Correspondence Register

- 5 tables, 19 endpoints: inward/outward registers per organisation, dispatch and broadcast, status transitions per the
  frozen rules, member-facing `my-applications`, `addressed-to-me`, and a Sakha-President-then-Kendra approval chain.

## 3. Attendance

- 4 tables, 21 endpoints: Weekly Sangha Puja marking with a live multi-marker register (conflict-safe, per-user rate
  limit, adaptive polling), reviews, exceptions and watch lists.

## 4. Sakha Re-parent Approvals and Membership Changes

- `organization_reparent_request` / `_step` (4 endpoints, GDR-007): a Sakha's parent changes only after the approval
  chain, except for Kendra Governing Body members and the super administrator.
- Member-initiated Sakha Transfer / Apply for Darshak (5 endpoints), Sakha Asana treated as a full Sakha (GDR-008),
  legacy-versus-new member numbering for Local Sakha and Kendra numbers (GDR-009).

## 5. Assets & Property (Module #22)

- 7 tables, 26 endpoints (`/api/v1/assets-property`), admin UI tabs Properties / Assets; physical-organisation custodians,
  custody history, disposal closes custody, optional "belongs to" and acquisition method.
- Decisions are recorded in GDR-010, which is still **Proposed** (owner approval pending).

## 6. Aadhaar (optional, GDR-011 — Proposed)

- Optional Verhoeff-checked number on registration and admin person forms; AES-256-GCM at rest
  (`api/services/aadhaar_service.py`), HMAC lookup hash, last-4 and reveal gated by `PERSON_VIEW_SENSITIVE`.
- Keys come from the environment only; without them the app starts and a capture returns 503.
- The legal/compliance question (Aadhaar Act / UIDAI / DPDP) is **open**; no legal conclusion is drawn.

## 7. Live Refresh

- One poll per page of `GET /api/v1/live/changes` reading `nss.live_change_marker` (55 watched tables, statement-level
  triggers). Covers claims (including an open claim's detail), Users, Organizations, directories, Governance
  (bodies, assignments, elections, catalogue, Advisory Board dashboard), Correspondence, Assets & Property and the
  member dashboard. A tab with an open form shows a "new updates" banner instead of reloading.
- Not on the feed by design: election tally/ballot tables; attendance lists (the live register has its own poller).

## 8. Audit and Diagnostics

- Audit-actor foreign keys on every `*_by_sangha_sevi_pk` column (build Phase 13c, idempotent).
- Admin tabs System Event Log and Live Change Markers (`AUDIT_VIEW`); recursive CTEs capped by a shared depth limit.

## 9. Reliability and Performance

- Database pools wait for a free connection (`DB_POOL_WAIT_SECONDS`, then 503 + `Retry-After`) instead of failing with a
  500, replace closed or idle-dead connections (`DB_POOL_PING_AFTER_SECONDS`), and use TCP keepalives; writes share
  the same guard.
- Response compression (`GZipMiddleware`); every page ran `init()` twice via `x-init="init()"` — fixed.
- Alpine `x-show` layout fix (display classes instead of inline styles) and the `x-if` single-root fix on the register page.

## 10. Build and Deploy

- Build phases 11b–11h and 13b/13c added; `render_build.sh` mirrors `02_build.sh`. Dead trailing `ALTER` "safety nets"
  removed from eight table DDL files (a table's DDL is skipped as a whole once the table exists).
- Render deploys on Python 3.14.0 (no cp315 wheels yet for `pydantic_core` / `psycopg2-binary`); `deploy/` holds the DEV
  and PROD env templates and the Neon setup SQL template; the hard-rebuild steps are in the `render_build.sh` header.

# Known Gaps

- GDR-010 (Assets & Property) and GDR-011 (Aadhaar) are Proposed; the Aadhaar legal review, key custody and retention
  questions are open. No Aadhaar keys are configured anywhere.
- The Render DEV build succeeded on 2026-11-09 (phases 0–14), but the DEV database held old-shape tables and needs
  `DROP SCHEMA nss CASCADE;` plus a redeploy; PROD has not been rebuilt. The pool, compression and `init()` fixes are not
  yet deployed. Secrets pasted into a chat session should be rotated.
- Attendance list tabs, `assignSakha`, the member `attendance` and `sendApplication` tabs are not on the live feed.
- `admin.html` (~860 KB) is still large; lazy-loading tabs is a deferred option (see `CLAUDE.md`).
- Forgot-password OTPs are never delivered (only visible via `otp_debug`); the `.ps1` build scripts have never run on Windows.
- Deferred: Programmes & Events, Finance, Kumari/Kishor/Sevak (Tier 9), Mahila (Tier 10), i18n, mobile/email verification.
